# Começar com o que tens
[Início](../README.md)

O primeiro objetivo é terminar um ciclo pequeno. Não precisas de instalar ferramentas de programação nem recuperar todo o arquivo antes de começar.

## 1. Escolhe um problema real
Escreve: “Quero ajudar [pessoa] a compreender/fazer [ação]”. Usa algo que já estudaste ou executaste. Se ainda estás a investigar, apresenta-o dessa forma.
Escolhe uma competência principal: explicar, escrever, pesquisar, editar ou interpretar dados.

## 2. Reúne o mínimo
Uma nota tua ou fonte identificada, um equipamento que grave som compreensível e um local para guardar os ficheiros. Verifica os recursos que já existem antes de comprar.
Se a ligação falhar, grava localmente. Uma gravação posterior não passa a contar como transmissão ao vivo.

## 3. Copia o caderno
Abre [templates/ciclo.md](../templates/ciclo.md), copia-o para o teu ambiente de trabalho e preenche só briefing e fontes. Usa LIVE-001 apenas se ainda não existir esse ID. Uma tarefa existente pode fornecer o identificador.
Escreve três pontos e uma prática. Define o que deverá existir no fim: explicação, guião, peça ou decisão.

## 4. Executa e observa
Grava uma primeira prática curta, com duração que consigas rever. Explica o problema, mostra uma aplicação e resume.
Não é obrigatório transmitir esta primeira tentativa. Revê o som antes de uma sessão pública. Guarda a tentativa, incluindo as dificuldades.

## 5. Fecha a aprendizagem
Ouve a gravação. Identifica um acerto, um problema com timestamp e uma alteração concreta. Verifica os trechos que pretendes publicar.
A transcrição automática é uma ajuda; o original é a referência.

## 6. Produz e distribui uma peça
Seleciona um trecho com sentido completo. Prepara o título, contexto, formato e ação desejada. Faz a revisão de publicação e guarda a URL quando publicar.
Se ainda não publicaste, regista “produzido” ou “em revisão”, sem inventar uma URL.

## 7. Regista a próxima decisão
Preenche o que aconteceu e o que falta observar. Escolhe um exercício para a próxima sessão. As métricas podem chegar depois; a melhoria da explicação pode começar já.

## Está concluído quando…
- O material original é localizável.
- A análise cita pelo menos uma evidência.
- Existe uma entrega e o seu estado está correto.
- A próxima ação tem motivo e responsável.

## Se só houver energia para o essencial
Reduz o tamanho da prática e o número de derivados. Mantém origem, revisão e decisão. Se houver mais de duas sessões por analisar, revê a carga antes de aumentar a produção.

## Aprender o GitHub aos poucos
Repositório = pasta do projeto com histórico. Branch = versão de trabalho. Commit = conjunto de alterações guardadas com descrição. Pull request = proposta de revisão antes de integrar.
Para começar, lê os ficheiros e copia os modelos. Para contribuir, segue [este percurso](../CONTRIBUTING.md).
