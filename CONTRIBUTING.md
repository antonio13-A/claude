# Contribuir para o EM LABS
[Início](README.md)

## Uma alteração de cada vez
1. Identifica uma dificuldade real de execução ou compreensão.
2. Consulta o SOP existente e verifica se a solução já está documentada.
3. Cria uma branch de trabalho e altera apenas os ficheiros necessários.
4. Descreve o problema, a solução e a verificação na proposta de alteração.
5. Confirma links relativos, modelos e ausência de dados privados.
6. Submete uma pull request e aguarda revisão antes da integração.

Não é necessário programar. Uma instrução mais clara, uma fonte corrigida ou um erro explicado são contribuições úteis.
Usa português claro. Define siglas na primeira utilização. Mantém exemplos separados de resultados.
Se uma mudança afeta um modelo e um SOP, atualiza ambos e regista no CHANGELOG.
Issues destinam-se ao método; produção e prazos de sessões continuam no gestor de tarefas.

## Verificação proporcional
Documentação: ler o percurso como iniciante e conferir links/saídas.
Automação futura: testar entrada válida, repetida, incompleta e falha após criação.
Um teste não executado deve aparecer como pendente, nunca como aprovado.
