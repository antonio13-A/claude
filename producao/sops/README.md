# SOPs — Procedimentos Operacionais Padrão

> Um SOP (Standard Operating Procedure) é a receita escrita de uma tarefa recorrente: os passos exatos para a fazer bem, sempre da mesma forma, por ti hoje ou por outra pessoa amanhã. SOPs são o que te permitem escalar, delegar e automatizar sem perder qualidade.

---

## Porque escrever SOPs

- **Consistência:** o resultado é o mesmo, independentemente do dia ou do estado de espírito.
- **Delegação:** podes passar a tarefa a outra pessoa sem estares em cima.
- **Libertação mental:** deixas de decidir de novo o que já decidiste uma vez.
- **Base para automação:** o que está documentado passo a passo é mais fácil de automatizar.

> Regra prática: se fazes uma tarefa **três vezes**, escreve o SOP na quarta.

---

## Como escrever um bom SOP

1. **Um SOP, uma tarefa.** Não juntes processos diferentes.
2. **Título claro e verbo de ação** (ex: "Publicar episódio no host de podcast").
3. **Passos numerados**, curtos, um por linha. Cada passo é uma ação concreta.
4. **Sem ambiguidade:** se um passo depende de uma escolha, explica o critério.
5. **Inclui pré-requisitos** (o que precisas antes de começar) e **resultado esperado** (como sabes que ficou bem).
6. **Mantém atualizado:** quando o processo muda, o SOP muda. Um SOP desatualizado engana.

---

## Como organizar

- Cria um ficheiro por SOP nesta pasta, com nome descritivo: `sop-publicar-episodio.md`, `sop-editar-clip.md`, etc.
- Usa o template abaixo como ponto de partida.

---

## Template de SOP

> Copia daqui para baixo para um novo ficheiro `sop-[nome].md`.

```markdown

- **Objetivo:** [o que este procedimento consegue]
- **Responsável:** [quem executa]
- **Frequência:** [quando/quantas vezes]
- **Tempo estimado:** [preencher]
```
