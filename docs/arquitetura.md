Esta é uma arquitetura proposta. Não existe sincronização instalada por este repositório.
Não criar duas filas de produção: o trabalho editorial continua no ClickUp; as propostas de alteração do método podem usar issues do GitHub.

## Rastreabilidade
SRC (fonte) → LIVE (sessão) → EXT (trecho) → AST (ativo) → PUB (publicação) → MET (medição) → DEC (decisão).
BEN identifica uma referência de benchmarking; EVD, uma evidência; SOP, um procedimento.
Um ativo pode ter várias origens. Uma publicação é uma ocorrência, não um novo vídeo único. A decisão pode orientar uma série diferente da imediatamente anterior.

## Fluxos que se encontram
- Competência: diagnóstico, exercício, avaliação, reaplicação.
- Editorial: notas, gravação, análise, peça, distribuição.
- Mercado: hipótese, teste, observação, decisão.
- Prova: fonte, versão, resultado, reflexão, PAP.

## Estados
Planeado, em execução, produzido, publicado e medido têm significados distintos.
“Validado” exige declarar contexto, critério e evidência. Ausência de dados não equivale a zero.

## Regra para amanhã
Na tarefa da sessão, liga o caderno, os originais e os derivados. No GitHub, regista apenas melhorias do método e casos preparados para divulgação. Não publicar o conteúdo inteiro dos espaços privados.
